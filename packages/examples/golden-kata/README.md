# golden-kata

AgentForge's example agentic project: a **writer** agent that writes a coding kata and a **grader** agent that grades one, over a shared base layer. It is generated by the plugin and verified locally and on AgentCore before any consumer adopts a change.

## How it was generated

```bash
nx g @beruangai/agentforge:init
nx g @beruangai/agentforge:agentic-project golden-kata --directory packages/examples
nx g @beruangai/agentforge:agent --project golden-kata writer --procedure Write
nx g @beruangai/agentforge:agent --project golden-kata grader --procedure Grade
nx sync
```

Re-running any of them changes nothing; `nx sync:check` fails if a maintained file drifts from what the installed AgentForge generates. What is maintained, scaffolded and detachable is listed in [AgentForge's README](../../../libs/agentforge/README.md#the-nx-plugin). What follows was written by hand into the scaffolded files.

## What it holds

| Layer | Holds |
|---|---|
| `base/agentic` (`@beruangai/golden-kata-base`) | `kata.ts` — `KataSchema` (title, description, function name and signature, 3–10 cases as JSON text), `WrittenKataSchema`, `CaseResultsSchema`; `run-cases.ts` — `runCases(directory)`, each case of `kata.json` against `solution.ts` in its own `bun` process with a timeout, compared by deep equality; `kata-server.ts` — the in-process `kata` MCP server and its `run_cases` tool; `options.ts` — `baseOptions(directory)`: Haiku, the `project` setting source, the directory added, the server, read tools, `dontAsk`; `$claude/` — `CLAUDE.md` naming the kata's files, the `kata-style` skill |
| `agents/writer` | `Write({ topic, difficulty })` on a scratch filesystem: the agent writes `kata.json` and `solution.ts`, checks them with `run_cases`, and answers with the kata; the handler writes the answer back as `kata.json` and returns it with the solution and the `results` it computes |
| `agents/grader` | `Grade({ kata })` on a scratch filesystem: the handler writes the kata and its solution; the agent, read-only, scores `CLARITY`, `CASE_COVERAGE`, `SOLUTION_CORRECTNESS` and `DIFFICULTY_FIT` and sums up; the handler adds the computed `results` |

Each procedure has a 180-second budget and capped turns. The kata travels from writer to grader in the output and the input, never as shared files.

## Running it

```bash
nx run @beruangai/golden-kata:test
```

```bash
nx run @beruangai/golden-kata:assemble
```

```bash
nx run @beruangai/golden-kata:e2e
```

`test` is `runCases`' unit test. `assemble` builds the AgentForge, agentic and both agent images. `e2e` serves both agents locally — `serve-writer` and `serve-grader`, with the subscription token from `.env.serve.local` — the one secret either agent requires, since both layers' `secrets.ts` declare none of their own at the workspace root — and runs the suite against a real model through `goldenKataClient.local()`. The suite asserts only what holds whichever way the model chooses: each output parses, the grade scores every rubric criterion, and each `results` equals an independent run of the returned kata.
