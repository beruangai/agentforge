# Proposal

## Why

Both consumers orchestrate their agents from Temporal, and AgentForge gives them one piece of it: `procedureActivity` over the client. Everything else — the worker, its connection to Temporal, the workflow bundle, the image, the deployment, a local server, the mapping from a workflow's call to an agent's procedure — is wired by hand. TrendBot's hand-wired copy is where its worst failures lived: activities without heartbeats or cancellation, connection code in three places, cloud mode switched on by whether a key happened to be set, import aliases kept in the bundler by hand, two local servers, a whole-table grant. The ROADMAP's A5 leaves exactly this pending: generating the Temporal worker and workflow layer, and connecting a caller project to an agentic project.

Reading `procedureActivity` against the SDK also found a defect that a generated worker would make routine: the activity cancels its agent's task on **any** cancellation, and a worker shutting down cancels its running activities. Every worker redeploy would stop every agent run in flight — the failure §REQ302 exists to prevent.

## What Changes

- **§REQ710** enters the register: *a consumer's Temporal workflows call its agents' procedures as activities typed by their contracts, and its workers are generated, built, run locally and deployed without wiring by hand.*
- **A workflow project**, generated by a new `workflow-project` generator beside `agentic-project`: workflows, activities and one worker, under the same maintained / scaffolded / detached contract.
  - **Maintained**: the targets — the workflow bundle, the worker bundle and its image's build context, the lock of the image's runtime dependencies, a local Temporal server, the worker served locally; the worker entry; the Temporal connection, read from the environment; the client that starts the project's workflows and its task queue; the activities and workflow-side calls spanning the connections; the worker's `Dockerfile`; the project's construct in the shared constructs.
  - **Scaffolded**: a placeholder workflow, a placeholder activity, a unit test of the workflow against the local server, and the project's `secrets.ts`.
  - **Declared per layer**: AgentForge's layer requires the secret `TEMPORAL_API_KEY` and the variables `TEMPORAL_ADDRESS` and `TEMPORAL_NAMESPACE`; the project's `secrets.ts` adds its own, as an agentic project's layers do.
- **A connection**, generated by a new `connection` generator: the record that a workflow project calls an agentic project, from which every artifact spanning the connections is rendered — the dependency and path mappings, the worker's activities over the agentic project's client, the typed calls a workflow makes, and the construct's grant. One workflow project may call several agentic projects.
- **A workflow calls an agent's procedure typed by its contract**, `agents.goldenKata.writer.Write(input, { runtimeSessionId })`, the contracts imported as types only so the workflow bundle carries none of the agentic project's code. Each call defaults to a heartbeat timeout, so a lost worker is noticed in about a minute rather than at the attempt's timeout.
- **`procedureActivity` changes in place** (no consumer depends on it):
  - routing is passed per call — `(input, start)` — by the workflow, instead of derived from the input by callbacks fixed when the activity is built;
  - it cancels its task **only on a cancel the workflow requested**. A worker shutdown, a heartbeat timeout, a pause or a reset leave the task running, and the next attempt attaches to it.
- **The worker runs on Node**, never Bun, and deploys as an **ECS Fargate service** connected to **Temporal Cloud** with an API key, through a new `/infra` construct, `TemporalWorker`, and the workflow project's generated construct over it, which requires each connected agentic project's construct and grants the worker exactly their agents.
- **Locally, the Temporal CLI's dev server** — file-backed, with its UI — serves unit tests, local runs and hybrid runs (local orchestration, agents on AgentCore). No docker-compose server.
- **Dogfood: `packages/examples/golden-kata-workflows`**, connected to `golden-kata`: a workflow that writes a kata and grades it, verified end to end locally, hybrid, and with the worker on ECS against Temporal Cloud. `golden-kata-infra` deploys the worker beside the agents, and its stand-in caller role is replaced by the worker's.

## Capabilities

### New Capabilities

- `plugin-workflow-project`: generating a workflow project; its worker — connection from the environment, declared secrets, prebuilt workflows, shutdown; the local Temporal server; running the worker locally against local or deployed agents.
- `plugin-workflow-connection`: connecting a workflow project to agentic projects — the connection record, typed calls from workflows, the worker's activities, the project construct requiring and granting exactly the connected agents.
- `infra-workflow-worker`: deploying a worker with one construct — a long-running service on Temporal Cloud, serving when the deploy returns, least-privileged, draining when replaced.

### Modified Capabilities

- `client-task-calls`: the Temporal activity takes routing per call, and cancels its task only on a cancel the workflow requested.

## Requirements

- **Serves:** §REQ710 (new); §REQ701 (the same workflows and worker locally, hybrid and in the cloud, chosen by the environment, an unset choice failing at start); §REQ302 and §REQ305 (a worker redeploy leaves the agent's run going, and the retry attaches); §REQ304 (a cancel the workflow requests still stops the run); §REQ708 (the worker invokes exactly its connected agents); §REQ709 (generated, synced, detachable); §REQ705 (the worker reads only the secrets its layers declare); §REQ101 (a workflow's calls typed by the agents' contracts).
- **Leaves unmet:** Worker Versioning — a deploy replaces the worker, and a workflow changed while runs are in flight is guarded by the consumer with `patched()` (§ODO011, new). §REQ702 is unaffected: a procedure still runs against a fixture with no workflow engine.

## Interfaces

- **`/temporal` grows and changes.** `procedureActivity` becomes `(input, start)` and cancels only on a requested cancel; added `projectActivities`, `runWorker`, `temporalConnectConfig`, `connectTemporalClient` and `agentsFromEnvironment`. They sit in `/temporal` because they are the caller's side of the boundary, over the client.
- **A new entry point, `/temporal/workflow`**, safe inside the workflow sandbox: `proxyProject` and the default activity options. Separate because workflow code may not import activity or worker code.
- **`/infra` gains `TemporalWorker`.**
- **The plugin gains** the `workflow-project` and `connection` generators, and executors for the workflow bundle and the worker bundle; `lock` learns the worker's layer; sync renders workflow projects beside agentic ones.
- **Optional peers** grow by `@temporalio/worker`, `@temporalio/client`, `@temporalio/workflow` and `@temporalio/envconfig`, caret like the Temporal peers already there; ECS comes with `aws-cdk-lib`, already a peer.
- No change to the A2A wire, the task-process IPC, `/agent`, `/server`, the runtime or the harness. Temporal stays above the client ([ADR 0001](../../../adr/0001-four-layers-with-contracts-at-the-boundaries.md)).
- **[ADR 0016](../../../adr/0016-a-workflow-project-is-a-generated-caller.md)**, proposed, records the decisions; §REQ710 is in `REQUIREMENTS.md`, §ODO011 in `DESIGN_OPTIONS.md`, the platform facts in [`research/temporal.md`](../../../docs/research/temporal.md) (2026-09-30).

## Impact

- **Package**: `/temporal` and `/temporal/workflow`; `TemporalWorker` in `infra/`; the plugin's workflow-project artifacts, generators and executors.
- **Workspace prerequisite**: the Temporal CLI on `PATH` (`brew install temporal`), for workflow projects' `test`, their local server, and `integ` local. `.claude/rules/testing.md` records that a workflow project's `test` runs against the dev server, with `temporal --version` as a runtime input.
- **Examples**: `golden-kata-workflows` added; `golden-kata-infra` gains a VPC (public subnets, no NAT gateway — the worker needs only outbound traffic), an ECS cluster and the worker, and drops its `Caller` role. smoke-coverage's activity test moves to the new signature.
- **Credentials and operator steps**:
  - Temporal Cloud namespace `beruangai-agentforge.vwhld` with API-key authentication (done; its name is `TEMPORAL_NAMESPACE` in `.env`, so the local server creates the same name).
  - `TEMPORAL_API_KEY` in `.env.integ.local` for the test runner starting workflows on Temporal Cloud (done).
  - The worker's key is the Secrets Manager secret `agentforge/temporal-api-key` in `us-east-2`, created and set by the operator (done), and referenced by name as the subscription token is — outside any stack, so a deploy never starts the worker without its value and a `destroy` never deletes it.
  - Hybrid uses the local Temporal server, so no key: `.env.hybrid.local` must not set `TEMPORAL_API_KEY` (the worker refuses a key aimed at a local address), and the stale `.env.hybrid.local.example` is removed.
- **Docs**: ARCHITECTURE §1 (Temporal as a generated caller), §7 (workflow projects), §8 (entry points, layout), §9; ROADMAP A5; GLOSSARY — added: workflow project, connection, worker; README (maintained and scaffolded artifacts).

## Success criteria

- `golden-kata-workflows` is generated by `workflow-project` and `connection` from an empty directory, then its workflow written by hand; re-running every generator in the synced workspace leaves no diff, and `nx sync:check` passes.
- Its end-to-end test passes, starting the write-and-grade workflow and receiving its typed result, in three places: the local Temporal server with the agents in local containers; the local Temporal server with the agents on AgentCore; the worker on ECS on Temporal Cloud with the agents on AgentCore.
- `integ` local shows, against the dev server and a real worker, that a worker shut down mid-activity leaves its task running and the next attempt attaches to it, and that a cancel the workflow requests cancels the task.
- A workflow calling a procedure with the wrong input, or one the connected project lacks, fails to compile.
- The worker's construct fails to compile without `TEMPORAL_API_KEY` or a secret the project declares, and its role may invoke the connected agents and no other runtime, asserted on the synthesised template.

## Non-goals

- Worker Versioning, autoscaling, and a worker per task queue — one service at a fixed count, until a consumer's load or change pattern shows the need (§ODO011).
- Self-hosted Temporal in the cloud, Lambda workers, and a docker-compose Temporal locally.
- Generating the consumer's workflows beyond the placeholder, or its end-to-end tests.
- Starting workflows from a Bun process: the maintained client targets Node; a consumer's Bun process starting workflows is outside this change.
- Cancelling an agent's task when its workflow is terminated or reset rather than cancelled — the task ends at its time budget; the consumer requests a cancel when it wants one.
- S3 filesystems in `golden-kata` — the next, separate change of A5.
