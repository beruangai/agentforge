# `temporal-agent-harness` — Study

Read at `d7a55f8` (v0.4.0, pre-alpha) on 2026-09-20: Python, ~24k lines, plus a Svelte console, a Go connector, and a Nexus/MCP subsystem. **Not a dependency and not a model.** It is the mirror image of AgentForge — the entire agent loop is a Temporal workflow — so most of what it does well is downstream of a decision we deliberately did not take. This note keeps what transfers.

## Its shape, in one paragraph

A session is one long-running workflow. The model SDK's reason-act loop runs *inside* the workflow sandbox with the model client swapped for a stub that dispatches an activity. Model calls, activity tools, MCP calls and subagent turns are activities; the turn loop, tool approval, callback parking and every event publish are workflow code. Nothing is explicitly persisted: durable state is workflow memory rebuilt by replay. Its outward boundary is a Nexus service with `sendAgentMessage` / `pollMessages` / `approveToolCall` / `provideCallbackResult` / `queryAgentStatus` — close in shape to our A2A boundary.

## What transfers

- **Driving a remote agent turn from an activity** (`harness/subagent_activities.py`). One activity drives a long-running remote turn: it heartbeats a resume memo from a background task at `heartbeat_timeout / 2` rather than off stream events, which are sparse and unpredictable; the turn itself carries **no timeout**, liveness comes from the heartbeat window; the memo's *presence* is the already-sent flag, so a crashed attempt resumes consuming rather than re-sending; the consumed offset is mutated in place so the heartbeated memo stays current. This is our activity factory over the A2A client, already written in another language.
- **An idempotency key derived from activity identity** — `f"...:{workflow_run_id}:{activity_id}"`, stable across attempts. The same construction [ADR 0009](../../adr/0009-the-caller-supplies-the-idempotency-key.md) specifies for the factory's default. Their in-workflow executor accepts an idempotency key and silently drops it, which is the failure our conventions forbid by name.
- **Admission and execution as two halves, with the cursor as an *output*.** The accept handler contains no yielding await, mints the id, and returns a **stream cursor** with it; the work runs elsewhere. Three reasons: a caller can start streaming from a defined point; a caller can never supply a stale cursor after the side effect already happened; and a handler that ran inside the accept would deadlock a gated tool, because the client that must approve it is still awaiting the accept. The cursor is read from the real log head, not from a publish counter, because activity-published events enter the log by a separate path a counter would undercount.
- **Envelope-stamped routing metadata.** Events are a closed discriminated union; producers build only the payload and cannot set `agent_id` / `turn_id` / `message_id` / timestamp. Raw provider tokens are folded into semantic events *inside* the activity, so the lowest-level thing crossing a boundary is already typed.
- **Three things they got wrong, worth inverting.** Their UI keys frames on an offset the server never actually sends and silently falls back to hashing the payload, so two byte-identical events collide and the second disappears — **every event on a wire needs a monotonic per-stream sequence number, and a consumer should refuse to deduplicate without one**. Nothing caps or elides a payload before publishing, and their claim-check offload protects only the workflow's own payloads — **cap tool output at the producer**. And their resume cursor advances only on root events, so reconnecting mid-subagent-turn silently drops that subagent's remaining detail — **if work ever fans out, each sub-stream needs its own cursor from the start**; retrofitting one is a protocol break.
- **The control plane is excluded from the discovered interface.** Approval and callback-result endpoints are deliberately not advertised alongside message handlers, so a calling agent cannot rubber-stamp a gate or fabricate an answer.
- **Approval as a frozen, serializable policy, required at construction.** A tool only asserts `inherently_safe` as a hint; an ordered policy decides; the builder raises if no default is set. They shipped the fail-open version first and had to invert it.
- **Validators reject before state changes.** A malformed callback result is rejected at the boundary *without consuming the one-shot gate*, so the client can resubmit.
- **Provider throttling read from response headers** (`_invoke_model_activity.py`): `retry-after-ms` / `retry-after` / `x-should-retry`, retry on 408/409/429/5xx, everything else non-retryable, and the server's delay propagated as the next retry delay, with the model client's own retries disabled so the durable layer owns them. This is the only throttling logic in the repository.

## What does not transfer, and why

- **The durable agent loop.** Their SDK loop runs in the workflow sandbox with I/O stubbed to activities. The Claude Agent SDK is a subprocess doing its own I/O and tool dispatch; there is no seam to stub.
- **The unbounded in-workflow pause.** `wait_condition` with no timeout costs nothing while parked — no activity, no process, no connection — and replay rebuilds the conversation and the loop position. Every HITL feature they have is downstream of it. We cannot have it: one task is one OS process, and AgentCore caps a session at 8 hours of lifetime. See [`../DESIGN_OPTIONS.md`](../DESIGN_OPTIONS.md) §M.
- **Per-delta durability.** Every batched flush of streamed text is a Signal in workflow history; the only knob is a 50–100 ms batch interval, which trades UI snappiness for history events without reducing them.
- **Nexus as the tool transport.** Nine startup steps, three namespaces, two endpoints and six dynamic-config values to reach three hello-world tools. Their own handler docstring concedes the durability comes from the activity, not from Nexus.
- **Long-poll-update stream subscription, and the client-side k-way merge.** Each cursor holds an in-flight update and Temporal caps those at ten per workflow — a cap that turns out to be load-bearing for roughly 2,000 lines of merge machinery plus a 757-line design document: unmounting stopped children exists to free a poll slot, and a client that disconnects mid-poll cannot reclaim the parked update. Both are consequences of the transport, not of the problem.
- **"Durable replay" as a promise.** Their own comments describe reattaching from an older offset being answered from the oldest retained one *without the client being told*, and a client-side seam detector for it — which in this repository is inert, because the offsets it reads are never emitted. The lesson survives the correction: replay off a transport's retained tail is lossy in ways the client cannot see. If we want replay, we store the event log ourselves beside the task state.
- **Their throttling story for tools** — there is none. Stock worker defaults everywhere, retries disabled on the tool proxy because tools may not be idempotent, uncached `list_tools` rediscovery on every call. The absence is the finding.
- **Unbounded per-session state.** Resolved approvals and callbacks retained forever for idempotency; no continue-as-new; history grows with every delta batch.

## Calibration

Its design documents are longer than the code they govern and have already rotted: dangling links, one document referenced five times and absent, functions cited in files that do not contain them, and a whole entry point maintained for a caller shape nothing in the repository exercises. Read the code first; where the two disagree, the documents describe an earlier system.

## Worth remembering, not building

- **Observable state as RFC 6902 patches** on the event stream: a typed state object, mutation recorded through a draft, one patch per touched field, nothing published when nothing changed. Independent of Temporal; a better answer than periodic snapshots if a phase ever needs to expose intermediate state. Three details make it work: state is a **projection over a position in the stream**, not a subscription — "an arrival is not a position", so a viewer parked on a patch sees that commit; the patch applier reports the *resolved* pointer and never throws, leaving the document in a state the run really passed through; and because the snapshot is published once at the start, a consumer attaching later has patches against a document it never received, so the snapshot must be re-requestable or each patch must name the version it applies to.
- **Code Mode** — one `run_script` tool over a sandbox whose only capabilities are the agent's own tools as host functions, with the script type-checked against those signatures before it runs. The only thing in the repository that reduces model round-trips.
