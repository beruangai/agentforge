# Testing Rules

## Three tiers

| Target | Where | What | Runs | Credentials |
|---|---|---|---|---|
| `test` | Colocated `src/**/*.test.ts` | Units against nothing external; the kernel against a scripted `query()` | Every build | None |
| `integ` | `libs/agentforge/integ/<dimension>/<concept>/` | One live slice: something AgentForge relies on, against the real thing | Before publishing, never on every commit | Per dimension, below |
| `e2e` | `packages/examples/<example>/e2e/<place>/` | The whole path: a caller, the client or the Temporal activity, the agent's image, a real model, back as a typed outcome | Before publishing | The subscription token; AWS from A2 |

A live slice is integration however expensive it is; e2e means the whole path.

| `integ` configuration | Folder | Needs | Costs |
|---|---|---|---|
| `local` | `integ/local/` | Docker (the runtime with real task processes and DynamoDB Local lives here) | Nothing |
| `aws` | `integ/aws/` | The test role in `us-east-2` | Short-lived AWS resources |
| `model` | `integ/model/` | The subscription token | Inference |

`nx run @beruangai/agentforge:integ --configuration=local` runs one dimension; a subset by path after `--`. A concept goes in the folder of the most expensive thing it needs. A new dimension is a folder, a vitest project and a configuration — never a conditional inside a test.

**e2e lives with the examples** in `packages/examples/` because they are AgentForge's own consumers, generated by the plugin: the images are built from what the workspace installs exactly as a consumer's would be, and the test drives them through the project client. `golden-kata`'s `e2e` serves its agents first and runs the `local` project; `e2e-agentcore` deploys first and runs the `agentcore` project, as the test role. One vitest project per place the images run; a separate target, because each depends on a different build. `examples/` is detached reference, outside the workspace; its suites do not run.

## What earns a test

- **The higher the tier, the more a test must earn its cost.** A model test asserts something AgentForge relies on and cannot learn more cheaply, and only what holds whichever way the model chooses.
- **Test what AgentForge relies on and the platform does not guarantee** — all three: the design rests on it, the documentation is silent, ambiguous or wrong, and the answer can move. A documented guarantee is trusted. An observation nothing depends on is a dated research note.
- **A spike becomes a test only if its answer can drift.** One that settles a decision once is a sentence in an ADR or research note.
- **Every intermittent failure becomes a test**, in the layer that owns it.

## Mechanics

- Each tier is an `nx:run-commands` target running `vitest run` with its own config. The guard is the target: **no `skipIf`, no environment guards** — an integration test fails when its environment is missing.
- **`integ` and `e2e` are `cache: false`.** A platform's or a model's behaviour is not an input Nx can hash; a cached pass would replay without reaching it.
- A cached target (`test`) hashes every external dependency and declares the runtimes it shells out to as `runtime` inputs.
- `vitest.integ.mts` spreads the unit config rather than `mergeConfig` it (which would concatenate `include`), one project per dimension, one file at a time, long timeouts. `integ/aws/agentcore/` runs files in parallel because each owns a uniquely named runtime.
- No placeholder tests. Fixtures go in `__fixtures__/` beside what uses them.

## Credentials per target

A target gets exactly the credentials it uses, from `.env.<target>` — never `.env.local`, which Nx loads into every task.

- `integ`: `.env.integ` (committed) sets `AWS_PROFILE=agentforge--test-integ`, `AWS_REGION=us-east-2` (`integ/aws/test-role-permissions-policy.json`); `.env.integ.local` (ignored) holds `CLAUDE_CODE_OAUTH_TOKEN`
- `e2e`: the example's target reads `.env.integ.local` for the token; a container gets it by name (`-e CLAUDE_CODE_OAUTH_TOKEN`), never by value on a command line
- `test`: nothing. There is no `default` profile
- Tests never run in prod's `us-west-2`
