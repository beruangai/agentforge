# Developing with AgentForge

AgentForge runs a Claude Agent SDK procedure as an asynchronous, typed task, locally in Docker or on Bedrock AgentCore, and returns a typed outcome. One package, `@beruangai/agentforge`, is also an Nx plugin that generates and maintains the projects.

This skill loads from the developer's clone of the AgentForge repository. Its links point into that clone and are the reference: read them when a step needs detail. The skill holds the practice: what to write, in what order, and what is the consumer's.

## Rules that hold everywhere

- **Maintained files are AgentForge's.** `nx sync` rewrites them to what the installed version renders, and `nx sync:check` fails while one differs. Don't edit one. Detach it to own it. Scaffolded files (contracts, procedures, the base layer's options, every `$claude/`) are the project's from the start. The package README lists [which is which](../../../libs/agentforge/README.md#what-agentforge-owns).
- **Generated seams use generic names; the importer aliases them.** `import { contract as writer } from './contract.ts'`, `import { client as goldenKata } from '@<scope>/golden-kata/client'`.
- **The consumer owns side effects and their recovery.** AgentForge carries identifiers and enforces mechanical invariants only. It has no hooks around a run, no `onSuccess` and no queue.
- **No silent failure.** A missing input, secret or file throws, naming it. Never default over missing data.
- **Credentials belong to the target that uses them**, from `.env.<target>`, never `.env.local`. See [operating.md](references/operating.md).
